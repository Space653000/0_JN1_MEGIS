## 8. 已確認的規範差異與技術債

### 8.1 高優先、已由 work item 承接

1. **Spike maturity 誤標**：`artifacts/g0-cad/manifest.json` 現為 `PROTOTYPE`，但 V3 規定 `FEASIBILITY_SPIKE` 的 `maturity` 必須為 `null`。由 `V3C-MAT-001` 修正並加負向掃描。
2. **D1–D9 尚未完整落 ADR**：目前只有 V3 採用 ADR 與工具鏈決策，不能宣稱 §8.1 已滿足。由 `V3C-DEC-001` 施工。
3. **Determinism 定義不足**：現有 byte hash 與 deterministic round trip 不等於 V3 的 semantic fingerprint policy、header normalization 與 replay。由 `V3C-DET-001` 補齊。
4. **Artifact policy 未強制**：有 `.gitattributes`，但沒有 size budget、heavy artifact gate 與既有大型檔白名單。由 `V3C-ART-001` 補齊。
5. **歷史 Gate 缺 V3 review/sign-off**：`execution/reviews/` 與 `execution/signoffs/` 目前只有 README。由 `V3C-REV-001`、`V3C-ACC-001` 補齊。

### 8.2 G0/G1 遷移債

1. `G0-CI-001` 在 v2 已 done，但 V3 對 CI 新增 fingerprint replay、maturity scan、size budget、secret scan；舊 done 不重開，改由 V3C 與新 G0 work items 承接。
2. `G1-IR-003` 在 reference research 與 machine-readable envelope 之前完成，與 V3 最終依賴圖不同。現有 golden 被視為 transitional，不應直接升級為核准工程輸入。
3. `config/envelope/` 只有 README；runtime 不能載入它，也沒有 docs/config 一致性測試。
4. `ERROR_CODES.md` 只有 domain 保留表；現有 `GeometryErrorCode` 是 legacy enum，不符合 `MEGIS-<DOMAIN>-<NNN>` 全域 taxonomy。
5. `docs/research/` 只有 README；D8 所要求的 PCB、USB-C、螺紋與公差公開來源尚未形成研究紀錄。

### 8.3 依賴圖差異

V3 §26 的理想依賴要求 `G0-CI-001` 等待 G0-DET/G0-DEC、`G1-IR-001` 等待 G0-ACC、`G1-IR-003` 等待 G1-REQ/G1-ENV、`G2-CAD-001` 等待 G1-ACC。現有 queue 保留了 v2 已施工順序，並以 `V3_MIGRATION.json` 的 retroactive work items 與 V3C deferral 管理差距。

這是可追溯的遷移安排，不是最終合規狀態。`V3C-REV-001` 必須證明所有差距都有承接項；在 G2 acceptance 前，還應再次核對是否需要把 retroactive G0/G1 項目改成真正的阻塞依賴，避免「有承接項但可被排程略過」。

## 10. 建議施工順序與驗收關卡

依目前 WIP=1 與依賴圖，下一步不應跳到新功能，而應依序：

1. 完成 `V3C-DEC-001`：D1–D9 各有 accepted ADR、機器可讀索引、既有證據路徑與測試。
2. 完成 `V3C-DET-001`：建立 fingerprint policy 1.0.0、header normalization、binary STL 與重跑一致性。
3. 完成 `V3C-MAT-001`：修正所有 spike manifest maturity，加入 repository-wide negative scan。
4. 完成 `V3C-ART-001`：size budget、artifact policy、白名單與 CI gate。
5. 執行 `V3C-REV-001`：必須是全新 session、乾淨 checkout、同 commit 重跑，且至少一個新 boundary/negative case。
6. 完成 `V3C-ACC-001`：建立 E4 blueprint-change sign-off；使用者保有否決權。
7. 對 G0/G1 retroactive items 做依賴圖 reconciliation；在無法證明其不阻塞時，不應直接接受 G2。
8. 完成 `G2-CAD-004`、`G2-NEG-001`、`G2-REV-001`、`G2-ACC-001`。
9. 再依序施工 G3 規則與 maturity、G4 modules、G5 package、G6 真實 UI/AI、G7 Acoustic、G8 Robot。

每一小段仍應遵守：baseline → implement → targeted tests → full baseline → commit → push → GitHub Actions 同 SHA 綠燈 → 更新狀態檔。不得因報告顯示某 Gate 有部分能力，就跳過其 review、sign-off 或 negative corpus。

## 11. 結論

MEGIS 已經跨過「只有藍圖與畫面」階段：repository、可重建工具鏈、IR、migration、Reference Fixture 的核心 CadQuery 幾何，以及 V3 控制面都有可重跑證據。尤其 `G1-MIG-001`、`G2-CAD-001～003` 與 V3C 前三項不是空殼，均有程式、測試、artifact 與 Git commit。

但距離 V3 最終成功定義仍有顯著距離。最關鍵的中後段能力——正式規則與 maturity evaluator、Module/Graph、完整 package/BOM/drawing、真實 UI-to-engine、AI governance/KPI、Acoustic 與 Robot thin slices——目前都是 0%。因此最誠實的總結是：**控制基礎穩定、G2 核心幾何已部分成立、V3 相容補強正在進行；完整 MEGIS 產品尚未完成。**

建議下一步：維持 `V3C-DEC-001` 為唯一 WIP，先把 D1–D9 決策補記完成並同步 GitHub，再進入 determinism 與 maturity 修正。
