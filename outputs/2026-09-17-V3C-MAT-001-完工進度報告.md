## 3. Classification 與 maturity 的嚴格邊界

| Classification | 可否具有 maturity | 掃描器要求 |
|---|---|---|
| `DESIGN_RUN` | 可以，且不得為 `null` | 正式狀態 + evaluator provenance |
| `FEASIBILITY_SPIKE` | 不可 | 必須為 `null`，不可帶 evaluation claim |
| `UX_DEMO` | 不可 | 必須為 `null`，不可帶 evaluation claim |
| `BENCHMARK_CASE` | 不可 | 必須為 `null`，不可帶 evaluation claim |
| `TEST_FIXTURE` | 不可 | 必須為 `null`，不可帶 evaluation claim |

目前沒有實作 G3 `megis.maturity` evaluator。Scanner 只保證 manifest 不越界，以及未來 Design Run 必須留下 evaluator provenance；它不計算成熟度、不證明工程正確性，也不允許把 spike 升級成正式設計輸出。

## 4. 掃描與失敗模式

掃描器只選取檔名精確為 `manifest.json` 的 repository 製品，避免把 Engineering IR、UI view model、verification evidence 中名稱相同但語意不同的 `maturity` 欄位誤判。`.git`、`.venv`、`.temp`、`.cache`、`.pytest_cache`、`node_modules`、`dist` 被明確排除，且不跟隨 symlink，防止掃描越過工作區。

| 負向案例 | 錯誤碼 | 結果 |
|---|---|---|
| 缺 classification | `CLASSIFICATION_MISSING` | rejected |
| 未知 classification | `CLASSIFICATION_UNKNOWN` | rejected |
| 缺 maturity 欄位 | `MATURITY_MISSING` | rejected |
| 非 Design Run maturity 非 null | `NON_DESIGN_MATURITY` | rejected |
| 非 Design Run 冒稱 evaluator | `NON_DESIGN_EVALUATION` | rejected |
| Design Run maturity 為 null/未知值 | `DESIGN_RUN_MATURITY_INVALID` | rejected |
| Design Run 無 evaluator provenance | `EVALUATOR_PROVENANCE_MISSING` | rejected |
| evaluator version 空白 | `EVALUATOR_VERSION_MISSING` | rejected |
| input digest 非 64 位小寫 SHA-256 | `EVALUATOR_INPUT_DIGEST_INVALID` | rejected |
| manifest JSON 無法解析 | `MANIFEST_UNREADABLE` | rejected |

## 5. 施工中額外發現的 DET 回歸

重新產生 G0 CAD artifacts 時，原 DET test 暴露 DXF byte hash 在不同 Python process 間漂移。差異不是幾何 entity，而是 ezdxf `CLASSES` section 中 `LAYOUT` 與 `ACDBPLACEHOLDER` 的 registry 輸出順序。

處置不是放寬 L1 比較，而是把 CLASS records 依 class name 與 C++ name 排序，保留全部 record 內容與 entity section；新增測試會啟動兩個獨立 Python process，各自完整產生三種 artifacts，再逐 bytes 比較。更新後：

| 指紋 | 修正後值 |
|---|---|
| DXF L1 | `b3b5a988d77c9227220dbc2e2ef996f826e0a2223f6f95aa0b129da216b6b8e4` |
| DXF vectors L2 | `20c24406f980fed8d413dc6cbe53b3d2fdce508a846597d398ce48290bfa21dc`（未變） |
| Manifest L2 | `ecefee996726bf1b0e0054b7407500888ea5d0e7607ee918373a3d5dbc949186` |

因此，前一份 `V3C-DET-001` 報告中的 DXF L1 與 manifest L2 是當時 commit `ad0a8dd` 的歷史值；現行 tracked artifacts 以上表為準。L2 DXF 工程向量未改變，證明本次只修正 serialization order 與 classification semantics。

## 9. 未完成、風險與禁止誤讀

- Scanner 不是 maturity evaluator；目前不能產出、升級或核准任何 Design Run maturity。
- `ENGINEERING_REVIEWED` 與 `RELEASED` 仍不可達，D6 也仍未指定具名工程師。
- Scanner 只掃描 `manifest.json`；Engineering IR 的 `maturity` 是 schema contract，不是 artifact classification manifest。
- 現有 repository 只有 1 份實際 manifest。覆蓋 5 種 classification 的測試不代表已有 5 類正式 artifacts。
- 跨 process replay 已通過，但還不是跨 OS/architecture 的 semantic equivalence 證據。
- Git 目前仍追蹤 G0 STEP/STL/DXF/SVG 等 spike 重型製品；V3 §5.9 要求不改寫 history，但後續不得新增，必須由 `V3C-ART-001` 建立機器檢查與 ADR 白名單。
- Fingerprint 一致不代表工程、製造或安全正確。
